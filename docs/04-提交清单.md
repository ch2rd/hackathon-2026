# 04 · 提交清单

> 按顺序执行，**每一项都要亲眼确认**。截止前 2 小时冻结 `main`，之后只允许修演示阻塞级缺陷。

## 一、T-2 小时：代码与仓库

- [ ] `main` 分支 CI 全绿，本地 `bash scripts/verify.sh` 通过。
- [ ] 无 `.env`、密钥、Token、个人数据被提交（`bash scripts/check-repo.sh` 已扫描）。
- [ ] 无 `node_modules/`、`dist/`、模型权重、原始数据集等大文件（单文件 < 5 MiB）。
- [ ] 从干净目录克隆后，严格按 `README.md` 的「快速开始」能跑起来（**让没写过这个项目的人试一次**）。
- [ ] `CHANGELOG.md` 的 `[Unreleased]` 已整理为本次提交版本。
- [ ] `ATTRIBUTIONS.md` 里每个新增依赖、模型、素材都已登记。

## 二、T-2 小时：文档

- [ ] `README.md` 顶部信息填全：赛道、团队、成员、提交版本、演示链接。
- [ ] `docs/01-项目方案.md` 无「待填写」残留。
- [ ] `docs/02-技术架构.md` 的架构图与实际实现一致（图不是画的，是抄的）。
- [ ] `docs/03-评审对照表.md` 每个评分维度都有证据位置，状态已更新。
- [ ] `docs/06-团队分工与排期.md` 已更新为实际完成情况。

## 三、T-1 小时：演示材料

- [ ] 演示视频已录制并上传，链接可访问（**已退出登录状态测试过**）。
- [ ] 演示 PPT / 幻灯片已导出，且另存一份 PDF 作为兜底（`assets/`）。
- [ ] `docs/05-演示脚本.md` 已按实际时长排练至少一次。
- [ ] 断网、依赖挂掉、接口超时三种情况的兜底演示路径已准备好（录屏或预生成结果）。

## 四、T-30 分钟：提交动作

- [ ] 打标签：`git tag -a v0.1.0 -m "黑客松提交版本 v0.1.0" && git push origin v0.1.0`。
- [ ] 在赛题指定平台完成提交，**截图保存提交成功页面**。
- [ ] 确认提交的仓库链接 / 附件与本仓库当前 `main` 的 commit SHA 一致：

  ```bash
  git rev-parse --short HEAD
  git status --short   # 应为空
  ```

- [ ] 在团队频道里同步：提交时间、commit SHA、提交物清单、还欠什么。
