# 05 · 演示脚本

> 规则：**先写脚本，再录视频，最后排练**。评委记住的是故事，不是功能列表。

## 一、演示要素

| 项目 | 内容 |
| --- | --- |
| 总时长 | 待填写（通常 3～5 分钟，先确认赛题要求） |
| 演示形式 | 现场 / 录屏 / 两者都要 |
| 主讲 | 待填写 |
| 操作手 | 待填写 |
| 演示账号 | 待填写（**提前登录，避免现场输密码**） |
| 展示分辨率 | 待填写，字号调大，保证投屏可读 |

## 二、分镜脚本

| 时间 | 画面（屏幕上出现什么） | 讲解词（说什么） | 要点 |
| --- | --- | --- | --- |
| 0:00–0:20 | 痛点场景：一张真实截图或一段现状复现 | 「现在要做 X，得花 N 分钟，还经常出错」 | 用具体数字，不要形容词 |
| 0:20–0:40 | 一句话介绍 + 架构总览 | 「我们做了一个 Y，把 N 分钟压到 M 秒」 | 只讲一层架构，别展开 |
| 0:40–2:30 | 主流程实操：输入 → 处理中 → 结果 | 边走流程边解释每步在做什么 | 不要读界面上的字 |
| 2:30–3:00 | 关键指标 / 对比数据 | 「同样的输入，传统做法 X 秒，我们 M 秒」 | 数据来自 `docs/03` 的实测值 |
| 3:00–3:30 | 亮点功能 / 差异化 | 「别人做不到的是这一块」 | 只讲一个最强亮点 |
| 3:30–4:00 | 收尾：下一步计划 + 团队 | 「如果继续做，我们会先解决 Z」 | 留一个记忆点 |

## 三、演示前检查（提前 15 分钟跑一遍）

- [ ] 网络可用；若依赖外网，已准备好热点或本地降级。
- [ ] 演示账号已登录，数据已预置到「刚好能演示出效果」的状态。
- [ ] 关闭所有通知弹窗、聊天软件、无关浏览器标签。
- [ ] 浏览器缩放调整到投屏可读；隐藏书签栏。
- [ ] 关键接口预热过（避免首次调用冷启动超时）。
- [ ] 录屏软件已测试，麦克风音量已检查。

## 四、故障应对预案

| 故障 | 现场动作 | 兜底材料 |
| --- | --- | --- |
| 网络中断 | 切到本地模式，口述「这是离线版」 | 本地预置数据 |
| 模型 / 接口超时 | 切到缓存结果继续讲 | 预生成结果截图 |
| 服务崩溃 | 不现场 debug，直接放录屏 | 完整演示录屏 |
| 演示设备故障 | 换成备用设备 / 用 PPT 内嵌视频讲完 | PPT + PDF |

**铁律：现场超过 20 秒修不好，立刻切兜底，不要当着评委的面调日志。**
