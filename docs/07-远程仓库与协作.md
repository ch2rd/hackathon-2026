# 07 · 远程仓库与协作

> 一句话：**本地仓库别人连不上，必须先有一个大家都能访问的远程仓库。** 本文档规定队长的首次推送、队员的加入流程，以及日常协作循环。

## 一、远程仓库信息

| 项目 | 值 |
| --- | --- |
| 平台 | GitHub |
| 地址 | <https://github.com/ch2nd/hackathon-2026> |
| 克隆命令 | `git clone https://github.com/ch2nd/hackathon-2026.git` |
| 默认分支 | `main`（受保护，禁止直接 push） |
| 可见性 | 开发期 `private`，赛程结束按赛题要求改为 `public` |

## 二、队长：首次推送（只做一次）

### 1. 登录 GitHub

```bash
gh auth login
```

选 `GitHub.com` → `HTTPS` → `Login with a web browser`，浏览器里授权一次即可。
如果本机没有 `gh`，也可以跳过这一步，直接走下面的「手动建仓」方式。

### 2. 创建远程仓库并推送

**方式 A：用 gh（推荐，一条命令搞定）**

```bash
cd D:\黑客松
gh repo create hackathon-2026 --private --source=. --remote=origin --push
```

这一条会同时完成：创建远程仓库 → 添加 `origin` → 推送 `main`。

**方式 B：手动建仓（没有 gh 时）**

在 GitHub 网页新建仓库 `hackathon-2026`，**不要**勾选「Add a README / .gitignore / license」，然后：

```bash
cd D:\黑客松
git remote add origin https://github.com/ch2nd/hackathon-2026.git
git push -u origin main
```

### 3. 邀请队员

**方式 A：网页**

仓库页 → `Settings` → `Collaborators` → `Add people` → 输入队员的 GitHub 用户名或邮箱 → 选 `Write` 权限。

**方式 B：命令行**（`USERNAME` 换成队员 GitHub 用户名）

```bash
gh api -X PUT repos/ch2nd/hackathon-2026/collaborators/USERNAME -f permission=push
```

队员会收到邮件邀请，**必须点接受**才有效。

### 4. 验证推送成功

```bash
git remote -v          # 应显示 origin 的 push / fetch 地址
git log --oneline -1   # 本地最新提交
git ls-remote origin main   # 远程 main 的 SHA，应与本地一致
```

### 5. 保护 main 分支（强烈建议）

仓库页 → `Settings` → `Branches` → `Add branch protection rule`：

- Branch name pattern：`main`
- 勾选 `Require a pull request before merging`
- 勾选 `Require approvals`，数量填 `1`
- 勾选 `Require status checks to pass`，选中 CI 的 `仓库规范自检` 与 `提交信息规范`

这样直接 push `main` 会被拒，只能走 PR，符合 [CONTRIBUTING.md](../CONTRIBUTING.md) 的约定。

## 三、队员：加入流程

### 1. 接受邀请并克隆

```bash
git clone https://github.com/ch2nd/hackathon-2026.git
cd hackathon-2026
```

### 2. 配置提交身份（每台机器一次）

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱@example.com"
```

> 邮箱建议与 GitHub 账号邮箱一致，否则提交在贡献图上不会被关联到你。

### 3. 启用提交规范钩子

```bash
bash scripts/install-hooks.sh
```

之后不合规的提交信息、疑似密钥、`.env` 会在本地就被拦下，省得 CI 红一片。

### 4. 验证环境

```bash
bash scripts/verify.sh
```

看到「自检通过」就说明环境没问题。Windows 上请用 Git 自带的 bash，见 [CONTRIBUTING.md 第七节](../CONTRIBUTING.md)。

### 5. 开第一个分支

```bash
git switch -c feat/你的功能 main
```

## 四、日常协作循环

每天开工和收工都按这个节奏走，能避免 90% 的冲突：

```bash
# 1. 开工前先同步，永远从最新 main 切分支
git switch main
git pull --ff-only

# 2. 做自己的事（分支名见 CONTRIBUTING.md）
git switch -c feat/your-feature

# 3. 小步提交，提交信息遵守 Conventional Commits
git add -A
git commit -m "feat(模块): 做了什么"

# 4. 推送前先自检
bash scripts/verify.sh

# 5. 推送（首次推送新分支要带 -u）
git push -u origin feat/your-feature
```

然后在网页上开 PR，按模板填完，等 1 名队友 Review 通过、CI 全绿后 **Squash and merge**。

合并后清理：

```bash
git switch main
git pull --ff-only
git branch -d feat/your-feature
```

## 五、认证问题

Windows 上 Git 自带 **Git Credential Manager**，第一次 `git push` 会弹窗让你在浏览器里授权 GitHub，授权后凭据会存进 Windows 凭据管理器，之后不用再输。

如果弹窗授权失败，改用 **Personal Access Token**：

1. GitHub → `Settings` → `Developer settings` → `Personal access tokens` → `Tokens (classic)` → `Generate new token`
2. 勾选 `repo` 权限
3. 复制 token，在 push 提示输入密码时**粘贴 token 当作密码**

> token 等同密码，**绝对不要**写进仓库、脚本或 `.env` 后提交。`.gitignore` 和 pre-commit 钩子已经会拦，但别赌。

## 六、网络与代理

先检测能不能连上 GitHub：

```bash
git ls-remote https://github.com/git/git.git HEAD
```

报 `schannel` / `SSL certificate problem` / 超时，通常是网络或代理问题：

```bash
# 如果你本机有本地代理（常见端口 7890 / 1080 / 10809）
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# 不需要时撤销
git config --global --unset http.proxy
git config --global --unset https.proxy
```

国内网络访问 GitHub 不稳定时，可以改用 SSH 协议 + `ssh.github.com:443`，或改用 Gitee 镜像，但**竞赛提交以哪个仓库为准必须全队统一**。

## 七、常见错误速查

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `remote origin already exists` | 已经加过 origin | `git remote set-url origin <新地址>` 或先 `git remote remove origin` |
| `Updates were rejected because the remote contains work` | 远程有你本地没有的提交 | 先 `git pull --rebase origin main`，解决冲突后再 push；**不要**直接 `--force` |
| `Permission to ... denied (403)` | 不是协作者，或 token 没 `repo` 权限 | 确认已接受邀请；重新生成带 `repo` 权限的 token |
| `Support for password authentication was removed` | 用了账号密码 | 改用 Personal Access Token |
| `fatal: refusing to merge unrelated histories` | 远程和本地是两个独立仓库 | `git pull --allow-unrelated-histories`，或干脆重新 clone |
| `pre-commit` 拒绝了提交 | 钩子拦下了密钥 / `.env` / 大文件 | 按提示处理；确认无风险才用 `--no-verify`，并在 PR 里说明 |
| 中文文件名显示成乱码 | 终端编码问题 | `git config --global core.quotepath false` |

## 八、提交前的最后确认

推送后建议在网页上确认这几点：

- [ ] 远程 `main` 的提交 SHA 与本地 `git rev-parse HEAD` 一致。
- [ ] CI 是绿的（`Actions` 页）。
- [ ] 队员能正常 clone 并跑通 `bash scripts/verify.sh`。
- [ ] `README.md` 里的克隆地址是本仓库的真实地址。
